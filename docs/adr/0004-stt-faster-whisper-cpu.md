# 0004. STT на faster-whisper, работа на CPU

- **Дата:** 2026-10-16
- **Статус:** Accepted
- **Контекст задачи:** этап 2, ввод голосом, RTX 4050 (6 GB)

## Контекст

Пользователь может отвечать голосом. Нужен локальный STT для русского языка. При
этом 6 GB VRAM не позволяют держать STT и LLM на GPU одновременно.

## Рассмотренные варианты

1. **openai-whisper** — референсная реализация, но выше потребление памяти и
   медленнее.
2. **faster-whisper (CTranslate2)** — быстрее и экономнее, int8-квантование,
   удобный API, работает и на CPU.
3. Облачный STT — противоречит локальности и приватности.

## Решение

Мы используем **faster-whisper** (int8) с русским языком. Аудио из Telegram
(ogg/opus) конвертируется в 16 kHz mono WAV через **ffmpeg**. По умолчанию модель
запускается **на CPU**, чтобы не конкурировать за VRAM с LLM; при освободившейся
GPU допускается разовый GPU-батч.

`device` и `compute_type` задаются **конфигом** (`STT_DEVICE`, `STT_COMPUTE_TYPE`),
а не хардкодятся. Это точка расширения: при переезде на GPU нужной ёмкости STT
переключается на неё сменой конфига (см. ниже).

## Последствия

- Положительные: GPU свободна для LLM, файлы пользователя не покидают машину.
- Отрицательные: STT на CPU чуть медленнее — приемлемо для коротких голосовых
  сообщений. Требуется ffmpeg в окружении/образе.

## Переезд на GPU (расширение)

Когда появится GPU с достаточной ёмкостью, STT и LLM смогут жить в VRAM
одновременно. Объём работ — примерно **0.5–1 день**, преимущественно ops:

- переключить `STT_DEVICE=cuda`, `STT_COMPUTE_TYPE=float16` (код не меняется);
- поставить CUDA/cuDNN для CTranslate2 в окружение/образ;
- спланировать память (по ~3 GB на `large-v3` fp16) и, при желании, развести
  модели по GPU через `CUDA_VISIBLE_DEVICES`;
- ввести очередь/семафор на инференс: faster-whisper не потокобезопасен, а при
  многопользовательности сериализация по VRAM снимается.

Ключ к дешевизне — держать `device`/`compute_type` в конфиге и STT за интерфейсом
(`stt/transcribe.py`), не зашивая `cpu` в код.
