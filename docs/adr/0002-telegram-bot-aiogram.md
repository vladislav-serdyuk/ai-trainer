# 0002. Telegram-бот как транспорт, aiogram

- **Дата:** 2026-10-16
- **Статус:** Accepted
- **Контекст задачи:** этап 2 (прототип), выбор стека

## Контекст

Задание допускает любой транспорт: Telegram-бот, веб-приложение с голосовым
интерфейсом, навык для колонки. Требуется быстрый прототип с поддержкой текста и
голоса, демо-доступом и минимальными затратами на UI.

## Рассмотренные варианты

1. **Telegram-бот (aiogram)** — быстрый старт, встроенный ввод голосовых
   сообщений, бесплатный демо-доступ, async-фреймворк.
2. Веб-приложение с голосом — больше контроля над UI, но существенно больше
   работы (фронтенд, запись аудио, деплой).
3. Навык для умной колонки — высокий порог входа и ограниченный сценарий.

## Решение

Мы делаем Telegram-бота на **aiogram 3** (async). Голосовые сообщения приходят
готовым файлом ogg/opus, что удобно для STT. UI минимальный: меню выбора сценария
и режима, ввод текста/голоса.

## Последствия

- Положительные: минимум кода на UI, бесплатный демо-доступ, естественный ввод
  голоса.
- Отрицательные: пользователь привязан к аккаунту Telegram (учитываем в политике
  ПДн, см. [ADR-0010](0010-ethics-and-data-minimization.md)).
- Вне рамок: веб-версия при необходимости — отдельный транспорт поверх того же
  `pipeline`.
