# 0001. Вести журнал архитектурных решений

- **Дата:** 2026-10-16
- **Статус:** Accepted
- **Контекст задачи:** процесс разработки

## Контекст

Сейчас это проект для конкурса, и над ним работает **один человек**. Но он
задуман как задел на будущее: если проект вырастет, над ним, вероятно, будет
работать **команда**. Чтобы не перестраивать процесс позже, мы с самого начала
ведём документацию по практикам командной разработки — включая журнал
архитектурных решений.

Без журнала со временем теряется «почему»: в коде остаются только следствия, а
обсуждения приходится повторять заново — это особенно больно при онбординге новых
участников.

## Решение

Мы фиксируем каждое значимое архитектурное решение отдельным ADR в
`docs/adr/`. Формат и правила — в [README.md](README.md). Ведём журнал уже
сейчас, при одном разработчике, как если бы над проектом работала команда.

## Последствия

- Положительные: прозрачная история решений, быстрый онбординг будущих
  участников, меньше повторных споров; процесс готов к росту команды без
  перестройки.
- Отрицательные: небольшой overhead на оформление при одном разработчике;
  оправдан только для значимых решений, мелкие изменения ADR не требуют.
