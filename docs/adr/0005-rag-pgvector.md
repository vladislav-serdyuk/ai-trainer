# 0005. RAG на PostgreSQL + pgvector

- **Дата:** 2026-10-16
- **Статус:** Accepted
- **Контекст задачи:** этап 1–3, база знаний

## Контекст

Нужна база знаний из открытых источников с поиском по смыслу и обязательным
цитированием. Объём базы небольшой и меняется нечасто. Отдельная векторная СУБД
добавила бы компонент и усложнила развёртывание.

## Рассмотренные варианты

1. **PostgreSQL + pgvector** — векторный поиск в той же БД, где живут диалоги,
   источники и кейсы; меньше компонентов.
2. Специализированная векторная БД (Qdrant/Milvus/…) — быстрее на больших
   объёмах, но ещё один сервис и синхронизация данных.
3. FAISS/локальный индекс — просто, но неудобно связывать с метаданными и
   транзакциями.

## Решение

Мы используем **PostgreSQL + pgvector**. Источники и чанки хранятся рядом с
остальными сущностями, метаданные источника — в тех же таблицах. Эмбеддинги —
`multilingual-e5-small` (размерность 384), поиск — cosine. Опционально — реранк
через `bge-reranker-v2-m3` на CPU.

## Последствия

- Положительные: минимум инфраструктуры, единые транзакции и бэкапы, удобная
  фильтрация по метаданным (сценарий, тип источника).
- Отрицательные: уступает специализированным БД на очень больших объёмах; для
  нашей KB это некритично. Путь масштабирования — отдельный индекс/сервис.
