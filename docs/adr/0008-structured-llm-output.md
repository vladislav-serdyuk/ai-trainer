# 0008. Структурированный вывод LLM + валидация pydantic

- **Дата:** 2026-10-16
- **Статус:** Accepted
- **Контекст задачи:** этап 2–3, обратная связь «как у эксперта»

## Контекст

Задание требует строго заданных форматов обратной связи: «Это верно», «Вот что
можно улучшить», «Вот удачный пример ответа», а также ссылок на источники.
Свободный текст LLM не гарантирует ни наличия полей, ни формата, ни цитирования.

## Рассмотренные варианты

1. Парсить свободный текст регулярками — хрупко, ломается при смене модели.
2. **JSON по схеме + валидация pydantic** — явный контракт, воспроизводимость,
   единая точка контроля.
3. Нативный function/tool-calling на каждый формат — гибко, но сильнее завязано
   на конкретный провайдер.

## Решение

Ответ LLM — **JSON**, валидируемый pydantic-моделями. Используем портируемый
`response_format: json_schema`. При несоответствии схеме — один ретрай, затем
безопасный fallback-ответ. Схемы для режимов:

- Информационный: `{ answer, citations[] }`
- Тренажёр: `{ verdict, what_to_improve, example_answer, detected_mistakes[], citations[] }`

Валидатор — источник истины, поэтому миграция Ollama → vLLM
([ADR-0003](0003-local-llm-ollama-then-vllm.md)) не ломает контракт.

**Проверка цитат (2026-10-20).** `citations` проходят серверный allowlist: url
модели нормализуется и сверяется только с тем, что реально было в контексте хода
— чанками KB и результатами веб-поиска. Для KB метаданные (`title`,
`document_id`, `source_type`) берутся из БД, а не из ответа модели; для веба
принудительно `document_id=null`, `source_type="media"`. Всё вне allowlist
отбрасывается с логом. Так модель не может внедрить выдуманную ссылку.

**Фолбэк пустых цитат (2026-10-20).** Маленькие модели при structured output
часто возвращают `citations: []`, хотя фактически опираются на контекст KB
(промпт с требованием и примером схемы не помогает надёжно). Поэтому, если после
очистки список цитат пуст, а ретривер вернул чанки, к ответу детерминированно
прикладываются топ-чанки KB (с дедупликацией по url) — это честное приложение
того, на чём основан ответ. В тренажёре ту же роль играет слияние цитат модели
с BASE-цитатами кейса и RAG-выборки.

## Последствия

- Положительные: гарантированный формат ответа, легко тестировать, можно
  проверять корректность цитат программно; allowlist делает это проверкой, а не
  пожеланием.
- Отрицательные: промпты и схемы должны развиваться согласованно; при жёсткой
  схеме возможны ретраи — компенсируется fallback'ом. Если модель ошибётся в url
  (опечатка, другой регистр пути), корректный по смыслу источник потеряется —
  компенсируется тем, что метаданные KB и так приходят из БД, а ответ остаётся
  валидным без цитаты.
