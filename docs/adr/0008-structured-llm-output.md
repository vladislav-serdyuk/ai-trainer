# 0008. Структурированный вывод LLM + валидация pydantic

- **Дата:** 2026-10-16
- **Статус:** Accepted
- **Контекст задачи:** этап 2–3, обратная связь «как у эксперта»

## Контекст

Задание требует строго заданных форматов обратной связи: «Это верно», «Вот что
можно улучшить», «Вот удачный пример ответа», а также ссылок на источники.
Свободный текст LLM не гарантирует ни наличия полей, ни формата, ни цитирования.

## Рассмотренные варианты

1. Парсить свободный текст регулярками — хрупко, ломается при смене модели.
2. **JSON по схеме + валидация pydantic** — явный контракт, воспроизводимость,
   единая точка контроля.
3. Нативный function/tool-calling на каждый формат — гибко, но сильнее завязано
   на конкретный провайдер.

## Решение

Ответ LLM — **JSON**, валидируемый pydantic-моделями. Используем портируемый
`response_format: json_schema`. При несоответствии схеме — один ретрай, затем
безопасный fallback-ответ. Схемы для режимов:

- Информационный: `{ answer, citations[] }`
- Тренажёр: `{ verdict, what_to_improve, example_answer, detected_mistakes[], citations[] }`

Валидатор — источник истины, поэтому миграция Ollama → vLLM
([ADR-0003](0003-local-llm-ollama-then-vllm.md)) не ломает контракт.

## Последствия

- Положительные: гарантированный формат ответа, легко тестировать, можно
  проверять корректность цитат программно.
- Отрицательные: промпты и схемы должны развиваться согласованно; при жёсткой
  схеме возможны ретраи — компенсируется fallback'ом.
